状态REVIEW。此目录仅处理常规回归与固定发行版审计的适用边界；来源、geometry、合同及根依赖不改。

集成仓库的常规回归入口：

```powershell
python -B examples/a01/integration-R1/verify.py '<新的证据目录>'
```

它运行A01、C01、A02及离线登录工具测试，重放固定URL反例并消费/搬运旧和R3两书样例。需要固定集成父版本中的A02文件；仅有A01分支时不宣称该全入口可运行。`--focused`仅供A01损坏负对照，不是全套结果。

常规测试继续核对旧R3参照的固定SHA256、971条、25个明确候选及历史资源严格字节政策；实际字节审计使用 `tests/fixtures/a01/integration-R1/` 内从旧Git提交提取的固定原件。当前仓库的调度文档可以合法演进，不能把它们当旧发行版字节。

`examples/a01/R3/verify.py`、其旧清单及所有旧证据均未改。该入口仍只适用于原冻结发行版及其原参照；新修订修改了旧测试文件，因此不得在新集成树运行旧入口并声称仍匹配原发行版身份。需要验证旧发行包时，完整导出 `180bb1e86fb2a7eb1546be85af70f466f069daf5` 后运行它。

作者侧 `exercise.py --patch <确切补丁提交> --out <新证据目录>` 从固定主目录父版本 `4946b8ab307f88bdc25c14ace5ead774e3119fc5` 与补丁父版本构造临时集成对象。Git操作都从原A01工作树显式调用；不会更新主分支。它实际使用默认Git checkout及无Git原字节导出分别运行常规入口，另在新副本破坏源码/固定输入以证明失败，最后在原冻结A01发行副本检查旧R3门禁的原件与损坏拒绝。所有父版本、补丁身份、磁盘表示、命令、退出码和清理记录写入新证据。

没有为一般checkout新增换行候选、改属性、规范化输入或降低损坏拒绝规则。本修订不处理D01、S01、N15、平台或B确认。详见 [执行报告](../../../docs/tasks/A01-integration-R1-execution-report.md)。
