# 更正说明：page_index off-by-one，以及被它误导的两个结论

> 本文**更正** `README.md` 2.3 节与 `data/derived/verify_report.md` 第 3 节的部分结论。
> 两份文档的原始结论基于**错误的页图配对**，请以本文为准。

---

## 1. 根因：标注 `page_index` 与实际页图整体错位 1

平台标注记录里的 `page_index = N`，对应的 OSS 页图是 **`{file_id}_page_{N-1}.jpg`**：

| 标注 page_index | 正确页图 | 我此前误用的页图 |
|---|---|---|
| 8 | `46006966_page_7.jpg` (1178×1673) | `page_8.jpg` (1176×1681) |
| 9 | `46006966_page_8.jpg` (1176×1681) | `page_9.jpg` (1179×1671) |
| 10 | `46006966_page_9.jpg` (1179×1671) | `page_10.jpg` (1175×1674) |
| 234 | `46006966_page_233.jpg` (3467×1615) | `page_234.jpg` (3465×1615) |

两个编号只差 1，**用错不会报错**，只会让所有坐标"看起来有点错但又不完全错"，
从而被误判成缩放/平移问题。这是本项目踩过的最贵的一个坑。
权威定义见 `tools/page_mapping.py`。

## 2. 证据（两条独立路线，互为交叉验证）

### 证据 A：跨模态逐像素互相关（决定性）

平台会把每个 `rect_bbox` **从源图上真实裁一块图**存到 `annotate_images/`。
把这张裁剪图与候选页在 bbox 原点做归一化互相关（NCC），在哪张图上能对上，
就直接证明哪张是源图。复现：

```powershell
python tools/verify_page_mapping.py      # 需要先把 annotate_images 裁图放到
                                         # data/derived/analysis/coord_evidence/annimg/
```

结果：**36/36 个框都是 `page_{N-1}` 更匹配**；35/36 达到 NCC ≥ 0.5，绝大多数 >0.9。
而 `page_N` 一侧的 NCC 基本在 0 附近（纯噪声）。示例：

| 框 | NCC(page_N) | NCC(page_{N-1}) |
|---|---|---|
| question p8 ord1 | 0.007 | **0.998** |
| choice p8 ord2 | −0.005 | **0.996** |
| question p9 ord8 | 0.067 | **0.993** |
| question p9 ord12 | 0.022 | **0.988** |
| analysis p234 ord10 | 0.066 | **0.937** |
| answer p234 ord1 | 0.276 | **0.937** |

> 踩坑记录：第一版脚本假设裁剪图带 1px 边框、先去掉边框再比对，导致对齐整体偏移，
> NCC 从 0.99 掉到 0.60，几乎掩盖了这个发现。**裁剪图与 bbox 是等尺寸、无边框的。**

### 证据 B：OCR 语义校验（独立）

用 RapidOCR 对两套映射各跑一遍：

| 判据 | 错误映射 N→page_N | 正确映射 N→page_{N-1} |
|---|---|---|
| 框 OCR 有文本 | 14/21 | **21/21** |
| choice 框真的出现 A./B./C./D. | 0/5 | **5/5** |
| 框文本 vs 整页 OCR 相似度均值 | 0.82 | **0.94** |

语义级样例：p8/ord1 的 choice 框在正确映射下得到
`A.-4,2 / B.-4x，2 / C.4x，-2 / D.3x²，2`，与该页印刷第 1 题选项逐字一致。

## 3. 因此被推翻的两个结论

### 3.1 推翻："页 234 的框与页图之间不存在可离线复原的平移-缩放关系"

**这条结论是错的**，错在把 `page_index=234` 的框与 `page_234.jpg` 比对。
正确配对下（`page_233.jpg`），**帧像素完全对得上，NCC≈0.94**。

真实情况是：

- 页 8/9/10 的框与其正确页图**同坐标空间、尺度 1:1**，
  `rect_bbox` 可以直接当像素坐标真值使用；
- 页 234 的框在 `page_233.jpg` 上也是**像素精确**的（NCC 0.89–0.98），
  只是这批答案的落点在图的**左侧窄带**（x 仅到 594），
  而这张图横向拼了多页，所以看起来"只用了 17% 宽度"。
  **这不是坐标空间不一致，是内容本来就落在左侧窄带。**

### 3.2 推翻："页 8 的框越界 5.09px"

该框（`x2=1181.09`）属于 `page_index=8`，正确页图是 `page_7.jpg`，**宽 1178**，
越界量是 **3.09px** —— 与交接包原始记录的"超 3.09px"**吻合**。
我此前用 `page_8.jpg`（宽 1176）算出 5.09px，是配对错误导致的。

## 4. 仍然成立的结论

- **页 233/234 是多页扫描拼合版面，不是"六栏答案表"**（贯穿式空白沟判据，与配对无关）。
- **历史 `choice` 框是 4 选项合 1 框**，与业务要求的"每选项独立一框"粒度不同，
  不能当选项级真值（与配对无关）。
- **`verified` 全为 0**、以及页 234 的 2 处跨类重叠（analysis ∩ answer 占较小框 91.1% / 100%），
  这些是框之间的相对几何关系，与配对无关，结论不变。

## 5. 方法论教训（值得写进项目规范）

1. **先用强证据锚定"哪张图"，再谈"坐标怎么变换"。**
   我们有平台自己裁的图，这是最强的锚——裁剪图能对上，就不需要猜缩放和平移。
   我此前先做缩放/平移拟合，方向反了。
2. **不要把"看似合理但未锚定"的相关性当结论。** 我早先用互相关时用了错误的模板边框，
   得到"N 侧胜出 5/36"的混合结果；如果就此收尾，会得出模棱两可的错误结论。
   修掉一个 1px 的对齐 bug 后，证据从"混合"变成"36/36"。
3. **OCR 置信度对"框选错区域"零警示。** 错误映射下，落在页面标题上的框
   OCR 返回 `1.2 一元二次方程的解法`，置信度 0.957；返回单字"为"时置信度 0.99994。
   所以**不能用 OCR 置信度做框正确性的判据**。
4. **一切坐标产物都要带"参考图像标识"**（file_id + page_index + 页图文件名 + 画布尺寸）。
   缺了它，off-by-one 这类错误可以潜伏到很晚才被发现。

## 6. 对下游的影响

| 影响面 | 变化 |
|---|---|
| 评测真值 | 页 8/9/10 的文字框现在**可以**当像素真值；页 234 也可用（同一图、像素精确） |
| 选项级评测 | 仍不可用历史 choice 框（合框口径），需自建选项级标注 |
| 坐标系标定（原方案段 1） | 复杂度**大幅下降**：记录坐标就是原图像素坐标、1:1，不需要标定缩放矩阵 |
| 仍需线上确认的事 | 只剩"平台查看器画布尺寸"这一项，用于交叉确认，不再是阻塞项 |
| 答案页处理 | 仍需按拼合面版切子页，但切完后坐标可直接复用，无需换算 |

**结论：原先被判为"最大风险"的坐标系问题，实际是命名错位造成的假警报。
这条线上不再需要设计复杂的坐标标定环节，方案可以简化。**
