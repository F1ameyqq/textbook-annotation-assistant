## 实测确认的关键结论

### 1. 第 234 页不是「六栏答案表」，是多页扫描拼合版面

| 页(0基索引) | 尺寸 | 墨迹% | 内部纵向空白沟 | 结论 |
|---|---|---|---|---|
| 7 | 1178×1673 | 2.48 | 0 | 单一页扫描 |
| 8 | 1176×1681 | 1.21 | 0 | 单一页扫描 |
| 9 | 1179×1671 | 1.74 | 0 | 单一页扫描 |
| 10 | 1175×1674 | 1.10 | 0 | 单一页扫描 |
| 233 | 3467×1615 | 1.88 | 5 | **多页扫描拼合** |
| 234 | 3465×1615 | 2.68 | 3 | **多页扫描拼合** |

判据是**贯穿式**空白沟（某列的最长连续空白 ≥ 该方向总长的 70%，宽度 ≥12px）。
这直接影响原计划「六栏答案图分栏出裁片」的实现方式。

### 2. 第 234 页的历史框不能当坐标真值

15 个框的 `x` 只用到 `0–594`、`y` 只用到 `254–1164`，而页图是 3465×1615（仅占图宽 **17.2%**）。
四种映射假设逐一检验后**全部否定**：

| 假设 | 墨迹覆盖率 | 结论 |
|---|---|---|
| 原坐标直接用 | 2.832% | 框未框住文字 |
| 按 `3465/594≈5.8333` 缩放 | 0.330% | 更低 → 否定 |
| 平移 +71 | 2.828% | 无改善 → 否定 |
| 平移 +1100 | 1.953% | 无改善 → 否定 |

页 8 另有 `x2=1181.09` 而图宽仅 `1176` 的越界框（**超 5.09px**），
说明平台记录画布可能比 OSS 下载图更宽。

### 3. 历史 choice 框不能当选项级真值

历史 5 条 `choice` 全是**4 个选项合 1 框**，而业务口径要求**每选项独立一框**，粒度不同。

## 推荐方案

见 **[docs/solution.md](docs/solution.md)**：三层分离 + 坐标标定前置。

核心判断：**不让视觉模型直接输出坐标**。
本地检测/OCR 负责「边界在哪」，模型只负责「这段属于题干还是解析」。
理由是平台自身的历史数据都存在坐标空间歧义，再叠加一个会幻觉坐标的模型等于双重不确定性。

## 如何复现

```powershell
python tools/land_data.py                        # 拉页图 + 读历史标注（只读）
python tools/verify_data.py                      # 版面结构 + 坐标系校验，生成报告
python tools/build_release.py --target _release  # 构建脱敏发布包（含凭证复检）
```

依赖：`numpy`、`Pillow`、`requests`；OCR 路线另需 `rapidocr-onnxruntime` 或 `paddleocr`。

## 样本与操作边界

- 样本来自既有平台结果，**尚未独立核准为验收标准**；已有框存在越界、交叠等质量问题，
  不应直接作为准确真值。当前样本也没有同题跨页实例。
- 线上调查保持**只读**：没有新建、删除或修改标注内容，没有保存、提交或创建新的 OCR 任务。
- 未来写入测试需明确测试题与允许范围，**最终提交由人工负责**。
- 本项目**不接** `commit_unified_submit` / `commit_unified_submit_and_async_ocr` 等提交接口。

## 安全约定

- **不提取、不记录平台令牌与账号密码**，一切线上访问经由用户已登录的浏览器会话。
- `data/raw/api_evidence/*.redacted.json` 已移除整个 `requestHeaders` 块
  （原始响应含明文会话 JWT）。原始响应只保留在私有工作区，**不进入本仓库**。
- `tools/build_release.py` 在打包后会做一次凭证特征复检，检出即拒绝发布。
