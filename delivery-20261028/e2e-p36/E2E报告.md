## 二、耗时与 Token（实测）

| 环节 | 数值 |
|---|---|
| 出图（下载 + 42 行分割） | ~8 秒 |
| 看图定行归属（1 次 read_image） | — |
| 写 spec | — |
| 预览 + 看图验收（2 次 read_image，1 轮修正） | — |
| **整页合计（模型全程）** | **约 9,300 tokens / 约 8 分钟** |

分步累计（turn 32，从出图前到验收完成）：16,060 → 25,317 tokens，**增量 9,257**。

失败成本（另计）：3 次子智能体尝试全部在 3–10 次调用后死掉，浪费 **17.6k tokens**（8,620 + 4,380 + 4,618）。

## 三、成本结构结论

| 环节 | 每页 token | 说明 |
|---|---|---|
| 出图 / 预览 / 提交 | **0** | 纯脚本（ego 点击 + numpy/opencv） |
| **写 spec（模型判断行归属）** | **约 9–10k** | 含 2–3 次看图 + 1 轮修正；本页有跨栏题，属偏难 |

⇒ **规模化成本几乎全在 spec 这一步**。按 9.5k/页估：100 页 ≈ 100 万 tokens；
若用更小模型起草 + 人工抽查，可再降。

## 四、本轮暴露的问题（都已记录）

1. 行分割会把**长行切断**（Q5 的 `(3)(4)(5)` 那类），此时必须改用 `@x0,y0,x1,y1` 绝对坐标
2. 跨栏题必须写两段 `stem`，只写左栏会漏掉 (3)(4)(5)
3. 子智能体在当前环境下**不可用**（3 次尝试均 <1 分钟死亡、零产物），端到端只能主会话做

## 五、与人工对比

- 人工量一页（SOP 基线）：约 15 分钟
- 模型写 spec + 看图验收：**约 8 分钟，9.3k tokens**
- 交付包运行（提交阶段）：**0 token**
