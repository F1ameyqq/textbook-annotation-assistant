# A11 固定离线内核独立验收

依据 [A11执行任务](A11-limited-live-runner-offline-core.md) 和 [三天路线](../delivery-72h-plan-2026-10-19.md)。本文件只准备验收范围，不构成对未固定交付的派发；实际最终提交、清单、运行目录和启动回执由调度JSON及固定派发消息指定。

仅审新增普通单选最多五题的离线内核。真实平台适配器、文本wire、当前来源/目标及共同平台政策尚未具备，不得给真实业务PASS。作者原第一候选失败、第二最终候选与全部旧记录保留；作者成功后不再续派业务。

## 固定检查

1. 先核最终交付与产品commit、全新增范围、旧路径mode/type/blob、fixture和原字节清单、唯一suite结果及自有跨进程身份/逐进程结束释放。若缺必需固定材料先报告，不审浮动实现。
2. 从书面业务规则和公共合同独立推导期望：普通单选Q/W/W/W/W/A，输入与原图/内容/授权/policy绑定；离线批准和离线采用不能变成真实准入。全书追加顺序必须来自全书证据，不能只看目录max。检查首失败TARGET subject绑定的实际纠正。
3. 静态核不可覆盖intent/独占发送权/书级锁、崩溃与新进程重启拒绝重发、UNKNOWN停后继NOT_RUN、只读reconcile不能恢复发送权。只读/离线入口不得触发浏览器、网络或SQLite；未知真实文字接口明确拒绝。
4. 在独立隔离检出和自有临时输出中，仅一次作者冻结的17 case、T1–T8有限suite；用实际源路径/fixture/调用链核对负例命中层，不把作者日志当独立运行。期望应对照合同和原规则，不以错误计划与错误读回相等算通过。明确框、文本、旧状态、刷新/重开及自身资源释放各层。
5. 若suite未覆盖但静态发现范围内缺陷，报告精确源码位置和可复核依据；不自行加新场景、改产品、再跑或因额度压力放行。第二候选若失败，固定收口，不第三包或改名恢复额度。

## 额度与输出

独立每派发固定候选至多一次正常suite，任务累计最多两次尝试/一次成功。本次仅第二最终产品的第一次独立派发；作者已用两候选不重置。网络/平台/profile/真实书写入/安装/B脚本/SQLite/旧成功业务均为0。不改旧源码/合同/pins/根依赖或作者冻结测试。

只新增 `docs/evidence/A11/review/` 和 `docs/tasks/A11-limited-live-runner-independent-report.md`。报告写固定产品/输入/实际命令/实际结果、raw成员及自有PID创建和结束释放，标明接受的层和未具备的真实接口。独立不能自行记INTEGRATED，主调度核证后才有限ACCEPTED和范围集成。
