## 4. P2 实现必须维持的不变量

1. 通过公共入口验证合同、资产字节和精确引用；结构校验/封签不能代替资格校验。新入口拒绝旧样例自动获得新资格，旧归档解析与原样复现保持可区分。显式迁移生成新文件、新摘要及映射，原文件不变。
2. UNKNOWN 原回执、intent、核对尝试及失败证据追加保存；新 resolution 精确绑定原 plan/action/intent 和存在的 receipt。不得改旧 schema_version/重封签后冒称保留了原 UNKNOWN，也不得删除旧记录或过滤交换包解锁。
3. 每个效果之前提交持久 intent 和书级占有权依据；提交失败不调用目标。intent 或 DISPATCH_STARTED 不证明效果已发出/未发出；崩溃后的未决项先按 UNKNOWN 恢复。SQLite 事务不能覆盖独立目标效果。
4. 文件完整写入并校验后才提交索引；效果、响应、独立读回、回执落盘分别记录。文件缺失/哈希错、事务失败、库损坏/未知版本、配置指向不同库均失败关闭，不静默创建空库继续。
5. 书键稳定且不含 run/scope/action；启动时先从受控库扫描该书所有 run/scope 的未决集合，再接纳新工作。调用者自报空清单或旧账本 JSON 不能证明完整性；公共 validator 仅验同 scope 链，跨 scope 完整性由 runtime 当前事务验证。
6. 同机两个受控进程竞争时至多一个有效 owner；效果前核对 owner/generation，抢占后旧代次不能继续。占有权失效不清 UNKNOWN。保证限受控 mock/支持入口，不宣称阻止任意真实平台外部写者或恶意修改数据库。
7. 同计划动作只受理一次；同身份不同内容摘要拒绝。新 action/run/question/scope 不能绕过同书暂停；另一书必须保持隔离，包括合法多书包中夹带其他书 UNKNOWN 的 A02 R1 回归。
8. 目标状态独立跨进程保存，有独立读取入口和效果日志；不能通过同一数据库事务同时提交目标效果和 runtime receipt，掩盖保存后崩溃。故障后不能靠重建初始 mock 清除实际效果或暂停。
9. 已调用、可能已调用、未尝试及依赖未满足分别留证；多动作中断先输出完整 action 清单的 progress。NOT_ATTEMPTED 的 ABSENT/NOT_APPLIED 按 D04 处理，不靠无日志推定没有调用。
10. MATCH → RESOLVED_APPLIED，ABSENT → RESOLVED_NOT_APPLIED；CONFLICT/INDETERMINATE → STILL_UNKNOWN。每次恢复读取产生新观察时间/版本并绑定实际读回；不能复用旧快照仅改时间。前两者须完整相关范围、精确身份和摘要；部分生效、空列表或响应本身不能代替证据。
11. MATCH 后旧动作不重发；ABSENT 后旧动作同样不自动重发，必须重新快照、目标检查与规划。解决一项不解除其他未决项；新 UNKNOWN 或目标变化使旧解除依据失效。链分叉、循环、错书/范围/摘要/版本保持阻断。
12. 解除暂停由 runtime 对当前全部未决集合做事务核对，不接受 `resolved=true` 作为证据。后续模拟效果与只读 reconcile 命令分开；reconcile 不触发保存、自动修框或删除。
13. BatchReport/POST_APPLY 按冻结合同绑定解决链并计算有效状态；旧报告原样保留。框一致不等于内容核验；仍保持 PENDING、NOT_SUBMITTED，不输出 COMPLETED。未知分母、异常/跳过/未入图谱项不得消失。

每例运行新临时目录；使用真实独立 Python 进程和可重复屏障，不能仅捕获同进程异常来宣称重启恢复。只终止用例自己启动的子进程；退出后列明自有进程释放。不得删除原失败现场重新生成“干净成功”证据。

| 编号 | 必需场景 | 必须观察到的结果 |
|---|---|---|
| V01 | 正常多动作、重启后查询和再次提交同动作 | 持久目标与回执可读；效果不重复，来源和版本闭合 |
| V02 | intent 提交前/后、调用边界后、效果后、读回后、receipt 提交后分别中断 | 前置提交失败无效果；未决一律先核对；效果已生效但无回执时 MATCH 且效果次数仍为 1 |
