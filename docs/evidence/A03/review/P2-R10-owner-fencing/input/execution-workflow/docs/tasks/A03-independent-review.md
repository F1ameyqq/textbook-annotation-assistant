## 3. P2 独立检查矩阵（须另获同对话续派）

以下矩阵是必须验证的可观察行为，与执行任务 V01–V10 一并适用。作者命令复跑与独立反例分别记录；不能用同一状态函数同时生成 expected 和 actual。

| 编号 | 检查与独立构造 | 验收标准 |
|---|---|---|
| R01 | 被验提交、允许路径、导入环境、决策附件、旧样例与归档 | 源码/报告/证据归属明确；仅指定执行者修改批准合同范围；旧版本/失败文件字节保全 |
| R02 | 读取新类型/校验/公共入口；构造错计划、动作、书 scope、摘要和资源 | load/validate/资格门分工正确；缺引用/改字节/错身份拒绝，不能凭 seal 或结构成功发出效果 |
| R03 | 在 intent 事务前后、DISPATCH_STARTED 后、效果后、读回后及 receipt 提交后逐点终止进程 | 恢复使用新进程；效果前失败次数为 0；效果后无回执必须先读回，次数保持 1；日志标记不能证明调用已/未发生 |
| R04 | 目标存储与 runtime 库独立检查；结束执行进程后再读目标 | 目标实际效果跨进程存在；不靠回执反向造目标，不以共享事务消灭崩溃窗口，不重建初始 mock 抹掉效果 |
| R05 | 独立构造 MATCH、ABSENT、部分/重复效果、矛盾/截断/失败读回 | 仅充分证据可解决；CONFLICT/INDETERMINATE 保持暂停。reconcile 调用产生目标效果次数为 0 |
| R06 | 原 UNKNOWN、后续解决、新 UNKNOWN；链分叉/循环/错原 receipt | 原历史不变；只解决精确原项；不按时间戳挑有利结果，新未决优先，旧证明不能重复解锁 |

| R08 | 换 action/question/run/scope、旧 generation、换空库、漏注册项 | 支持入口拒绝绕过；状态库身份/完整性失败关闭，无静默空库续跑 |
| R09 | 两个进程通过屏障争抢同书；持有者中断、旧 owner 继续 | 有效 owner 唯一；效果前 owner/generation 再核对；不靠固定 sleep 证明竞争无误，不宣称对任意外部平台写者有约束 |
| R10 | 另一书单独包及包含他书 UNKNOWN 的合法多书包；同书多个历史包 | 他书未决不误暂停本书；同书未决不能遗漏；保留 A02 R1 原跨书失败用例并另造邻近输入 |

| R13 | 图谱/快照/政策版本变更、已解决后目标再变化 | 旧资格失效；新冲突留证并暂停，不覆盖历史解决结论或默认为 READY |
| R14 | 证据缺失/损坏、SQLite 事务失败、未知格式、迁移中断 | 有定位错误、原状态/历史可追溯；不删除库、清暂停或回退弱校验来完成 |
| R15 | 新旧合同入口、显式转换、旧 UNKNOWN 无 intent | 精确符合已批准设计；旧无 intent UNKNOWN 不解除；旧字节不变，不能改 schema_version 再封签冒充保全 |
| R16 | 真实/ORIGINAL/OBSERVED 来源及证据、S01 边界 | 全合成入口有效拒绝；旧归档可读≠新资格；S01 未被恢复成功消除，不宣称真实完整性已实现 |

## 4. P2 恢复合同与来源门禁的专门边界

1. 按主调度冻结字段核对 WriteIntent、ExecutionProgress、ReconciliationResult 的生产者与验证者；runtime 管事务/书级未决，reconciler 只比较，contracts 只验声明与引用。不得把题型规则、任意代码策略或浏览器指令放进恢复状态机。
2. C01 原门禁因 UNKNOWN 阻断，只能由新版本的合法解决链与当前 runtime 未决集合共同改变资格；不能删旧回执、忽略 scope、加布尔字段或省略历史。caller 提供的 hash/JSON 不证明库完整性。
3. 旧无 intent UNKNOWN 保持 LEGACY_UNRECORDED、不可解除；独立验证原字节归档及新运行真实本地 intent。不得临时要求任意跨版本解锁，也不得用迁移默认值补造历史。
4. S01 继续单独阻断；验收本任务全合成准入能拒绝真实/ORIGINAL/OBSERVED 来源及证据，不把 S01 全部未来能力变成本任务范围。A03 恢复通过不释放 I01 真实来源自动资格。
5. 未尝试动作若有完整独立 ABSENT，可否输出 NOT_APPLIED 依 D04；验收必须读取 `not_attempted/dispatched=false` 的事实证据，不能仅看回执结果。无充分证据的部分计划允许仅 progress，不能伪造完整 BatchReport。

## 5. P2 复现与报告

先复现作者最短命令和冻结列出的相关 A03/合同/A02 检查；再执行上述独立场景。记录真正导入位置、Python/SQLite/依赖版本、命令 argv、cwd、有限超时、退出码、进程身份、输入/输出路径及目标效果计数。正常、已生效但丢响应、明确未生效三条主路径均须可独立复现。

独立反例保存可搬运输入和必要资源、预期/实际、原回执与解决链、独立目标状态和日志；证据生成器不得覆写已冻结输入。若验收脚本有错，保留原失败、修正脚本并单独重跑，区分脚本错误和实现缺陷。

报告包含确切被验提交、D01–D08 决策附件版本、R01–R18 逐项结果、作者复现与独立检查、失败/跳过/未执行原因、范围和限制，结论为 ACCEPTED / REWORK / BLOCKED。关键失败给最小反例，不因原用例全过推断邻近约束全部正确。

统一清单覆盖报告与全部新证据（含 `.log`），记录长度/SHA256、自身排除和忽略文件；核对旧样例/旧报告/旧证据与基线字节一致，并确认退出时没有验收自有进程未释放。此清单是归档完整性证据，不代替功能结论。

只有批准范围全部满足才可独立建议 ACCEPTED。合同关键决策缺失、恢复只能维持暂停却不能完成被批准的继续路径、关键检查未运行或存有阻断反例时，不得以“部分可运行”给整项通过；报告具体恢复条件并交回主调度。主调度另行复现、接受和集成后才释放 I01，验收者不集成、不推送、不修改状态、不声称 B 接受或平台能力通过。
