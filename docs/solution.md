# 识别路线历史研究：检测器出坐标与语义判定

> 2026-10-16 M0 更正：本文保留历史实验，不是当前架构或公共接口。后续以 architecture.md、contracts-v1.md 为准。历史指标使用过不同参考框，不是独立业务验收成绩。

> 本文是四条并行调查（路线 A / 路线 C / 坐标系逆向 / 外部选型）汇总后的定稿。
> 所有实测数字都可追溯到 `data/derived/analysis/` 下的 JSON。

---

## 0. 一句话方案

**本地检测器只负责"边界在哪"，模型只负责"这段是什么"，后续配答必须综合目录、题号、小问、顺序和内容证据。
坐标问题已经查清（是命名错位，不是坐标变换），因此不需要坐标标定环节。**

```
[1] 取图（page_index - 1）
[2] 版面检测出候选框 + 选项逐个独立出框     ← 本地，零 API
[3] 角色判定 Q/W/A/E                        ← 规则优先，公式内容必须交给模型看图
[4] 组题配答：独立 question_id，题序仅为外部参考 ← 待实现
[5] 执行：写回平台（人工确认，不碰提交接口）
```

## 1. 核心设计判断：不让模型输出坐标

这不是偏好，是两条独立证据的结论。

### 外部证据（`vision_stack_research.md`）

| 证据 | 数字 |
|---|---|
| HiLEx（ICDAR 2025）同任务 | 微调检测器 mAP@50 **94.0%** vs VLM 零样本 81–83.5%（严格 IoU 仅 **59.0%**） |
| GroundingME（25 个 SOTA MLLM） | 最高 **45.1%**，拒答率几乎全 0 |
| Qwen 官方 issue | 坐标系在 2-VL→2.5-VL→3-VL 之间 0-1000↔绝对坐标**反复变动** |

社区主流拆解正是"检测器出框 + 模型判角色"——PaddleOCR-VL 官方方案自己也是用
PP-DocLayoutV2 当前置。

### 本地证据

`aocr` 实测：OCR 置信度**无法自检框选错误**。错误页配对下，落在页面标题上的框
OCR 返回 `1.2 一元二次方程的解法`，置信度 **0.9565**；返回单字"为"时置信度 **0.99994**。
如果坐标也由概率模型生成，这类静默错误将无法定位。

**因此：VLM 只输出离散标签（Q/W/A/E + 层级），绝不输出坐标。**

## 2. 地基：坐标映射与参考系（已解决）

**`page_index = N` → 页图 `{file_id}_page_{N-1}.jpg`**，且 `rect_bbox` 就是源图像素坐标：
**尺度 1.000、偏移 (0,0)、残差 <0.5px**。

- 定义：`tools/page_mapping.py`
- 复核：`tools/verify_page_mapping.py`（36/36 框在 `page_{N-1}` 上更匹配，35/36 NCC ≥ 0.5）
- 更正说明：`data/derived/CORRECTION-page-mapping.md`

**工程要求（两条硬规定）：**
1. 仅样书 46006966 的已验证页采用 `page_{page_index-1}.jpg`；新书重新核对来源映射。
2. 写回平台时必须用**同一套 1 基 `page_index`**，否则与历史框错开一页。

**原先设计的"坐标标定"环节取消**——原报告认为页 234 坐标空间不一致，
实际是配错页图造成的假警报。

## 3. 阶段 2：版面检测出候选框（本地实测结果）

`alayout` 的实现（`tools/route_a_layout.py`，纯 CPU，260s 跑完 6 张图）：

| 指标 | 实测值 | 说明 |
|---|---|---|
| Q 框 vs 历史框 IoU@0.5 召回 | **6/16 = 37.5%** | 历史框含大量留白，直接比会低估检测器 |
| Q 框 vs「历史框内墨迹紧致框」召回 | **12/16 = 75.0%** | 剥离留白后的真实检测质量 |
| 紧致框可及上限 | 12/16 = 75% | 任何"只框文字不留白"的检测器上限 |
| 检测器 vs 紧致真值 IoU 均值 | **0.6997**（中位 0.7918） | |
| 选项容器一致性 | **4/5 个历史 choice 容器内含我 4 个独立选项框** | 选项级切分粒度正确 |

**关键口径教训：** 历史框是"人画的带留白框"，拿它当 IoU 真值会系统性低估任何紧致检测器。
评测必须同时报三档：vs 历史原框 / vs 紧致框 / vs 人工复核框。
只报第一档会让方案看起来不可用。

拼合宽图切分：页 233 / 234 各切成 **6 个子页**，子页内检测后再回投全图。

## 4. 阶段 3：角色判定（规则优先，公式必须看图）

### 规则层（零成本，覆盖常规题）

- 行首"数字+顿号/句点" → 题干起点
- `A. B. C. D.` 或 `（1）（2）` → 选项 / 小问（**每选项独立一框**）
- `【答案】`「【解析】」→ A / E
- 页眉页脚模式 → 丢弃

`aocr` 实测：正确配向下题干 **14/14**、选项 **5/5**（逐字正确）、答案字母 **7/14** 干净。

### 模型层（只在必要时上）

**重要修正：不能只用 OCR 文本喂模型判角色。**
`aocr` 实测公式结构在 OCR 阶段就已丢失：126 行整页文本 + 99 行框文本里
`\frac` / `\sqrt` / `$` / `^` 出现 **0 次**；`−`→`一`、`+`→`十`、`|a|`→`la|`、
`D. 1/2` 被拆成三行 `1`/`D.`/`2`。

所以：**涉及公式的区域必须把裁剪图交给模型**，且只要求输出离散标签。
纯文本片段可以走规则或轻量分类，不必调用模型。

### 另一个坑：`type` 字段不可靠

`aocr` 实测：按 `type` 字段算解析只有 **1/14**，但按内容判定实际有 **5/14**——
`answer` 里混着单字母答案和整段解析。**不要用历史 `type` 当训练标签或评测真值。**

## 5. 阶段 4：配答

- 使用独立稳定的 `question_id`；`order_in_level` 是可能按目录重置的外部属性，不能充当全局主键。历史关联不能证明新候选已正确配答。
- 同时保存：书籍 + 目录路径 + 印刷题号 + 平台题序 + 来源页 + 子题号。
  印刷题号按课时重置，凭它全书匹配必然错配。
- 组合题父子结构、跨页续接保留在需求内。

## 6. 阶段 5：执行

- 写回字段：`rect_bbox / page_index(1基) / question_order /
  image_order_in_annotation_zone / order_in_page / parent_rect_id / directory_id`
- **只做增量建框/改框**；平台保存是增量式（零改动不产生请求，已实测）。
- **不接** `commit_unified_submit` / `commit_unified_submit_and_async_ocr`。
- 每次写入留回执并按 `rect_id` 读回校验；不一致就停下重读，不重发整题。

## 7. 成本控制

| 手段 | 效果 |
|---|---|
| 检测与切分全本地 | 出框零 API 成本 |
| 局部裁剪而非整页 | 大幅降 token |
| 规则优先，模型兜底 | 常规题完全不花钱 |
| 一图一次调用（批量判角色） | 避免一框一次 |

成本口径：**全部调用费用 / 人工验收通过题数**（失败跳过计入分子）。

## 8. 评测口径（不达标就是没做完）

1. 漏题率 / 重题率
2. 题干完整性 + **选项级**完整性（历史 choice 是合框，不可作选项级真值）
3. 答案解析归属正确率（注意 `type` 字段不可靠，需按内容判定）
4. 目录与题号重置处理正确率
5. 图表与公式保真度（OCR 路线已证会丢结构）
6. 跨页完整性
7. **人工修正比例**（最终验收指标）

**调参用过的题不算验收成绩**，需独立验证样本。

## 9. 选型结论（8GB 显存约束下）

全部锁定 Apache-2.0 / MIT，全本地跑，**暂不引入 VLM、不做量化**：

| 用途 | 选择 | 说明 |
|---|---|---|
| 版面检测 | **PP-DocLayoutV3**（≈131MB，Apache-2.0，官方语料含中文试卷） | 或最小依赖走 RapidLayout（Apache-2.0 / ONNXRuntime） |
| 方向矫正 + 去畸变 | **PP-LCNet_x1_0_doc_ori（7MB）+ UVDoc（30.3MB）** | **默认关闭，必须显式开启** |
| 公式识别 | **PP-FormulaNet_plus-S/M**（Apache-2.0，与已装 paddleocr 同生态） | Pix2Text（MIT）作交叉验证 |
| 可微调骨干 | DocLayout-YOLO（**AGPL-3.0**） | 仅离线对照，**不进交付物**（网络服务分发会触发 AGPL 义务） |

**许可风险清单：** DocLayout-YOLO = AGPL-3.0；Qwen2.5-VL-3B = qwen-research（非商用）
且 bf16 权重约 7.51GB 会占满 8GB；MinerU = 许可不明；HiLEx = 数据 CC BY 4.0 但代码无许可。

`PP-StructureV3` 的 `use_doc_orientation_classify` / `use_doc_unwarping` **默认是关闭的**。

## 10. 数据与标注规范

- **没有开源项目做"选项独立出框 + 题答配对"，必须自研**（外部调研明确结论）。
- 历史训练格式建议为 HiLEx 类别和 YOLO 归一化框；只适用于特定训练后端。当前通用接口使用原图像素框，内容类型与题目角色分开，平台 Q/W/A/E 由交付层投影。
- HiLEx 仅英文且粒度只到 Answer_Block，**不含 A/B/C/D 独立选项**，中文教辅数据需自建。
- 第一个里程碑建议：**人工标 20–30 页验证类别可分性**，再谈微调。
- 所有中间产物必须带"参考图像标识"（file_id + page_index + 页图文件名 + 画布尺寸）——
  缺了它，本次的 off-by-one 这类错误可以潜伏很久。

## 11. 已知风险

| 风险 | 对策 |
|---|---|
| 拼合宽图切分错误 | 用贯穿式空白沟判据；人工复核子页数 |
| 公式结构丢失 | 必须上专用公式模型；不指望后处理 |
| `answer`/`analysis` 内容混杂 | 按内容判定，不信任 `type` 字段 |
| 静默错位无法自检 | 坐标级校验（裁剪图互相关）+ 参考系元数据 |
| 样本过少（analysis 字段仅 1 条） | 先规则+弱标注扩样，再考虑微调 |
| 未实测项 | 公式识别 CER、平台写接口语义、VLM 在中文教辅上的实际表现 |

## 12. 需求缺口（需用户提供）
