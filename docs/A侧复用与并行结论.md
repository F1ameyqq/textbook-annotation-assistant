## 一、A 的做法（一句话）

**人不给坐标，只给"行归属"**：`{"n": 13, "stem": ["L03-L05"], "opt": ["L09x4"]}` →
脚本做行分割与坐标换算 → overlay 图人眼验收 → ego 驱动画框提交。

这是它效果明显好于我们全自动方案的根本原因，已用平台数据交叉验证：

| order | A 的产出 | 说明 |
|---|---|---|
| 91 | Q1 + **W4** + A1 | 4 个选项各自独立框（x 87–189 / 210–306 / 326–423 / 443–540） |
| 93 | **Q2** + A1 | 跨栏题：同一题两个题干框（左栏 + 右栏） |
| 90/92/94 | Q1 + A1 | 答案框只框答案值（最小 47×13 源像素） |

## 二、复用判断（实测级）

| 组件 | 能否复用 | 依据 |

| `measure_page.py` 行分割/坐标换算 | ✅ **能**，需参数化 canvas | 已写 `tools/measure_page_adapt.py` 跑通 p34，出 10 题干框 + 20 选项框 |

| `restorefn.mjs` | ⚠️ 已升级为条件轮询 | A 新提交把固定等待改成轮询（`e1baec95`），这块比我们的 sleep 强，值得抄 |
| `guide.py` / `prepare_page.py` | ✅ 新工具 | 一条命令跑 自检→measure→make→overlay，输出 `IMG_OK/PAGE/CHECK/VIEW/NEXT` |

**结论：测量层可直接用；提交层要么换 ego（已能离线装），要么改 2 处接 playwright。**

## 三、A 侧的安全缺口（我们的闸门要补上）

A 的 pageRun 有 9 项检查，但**缺**：

1. **画框模式没有直接断言**（没进"题目(Q)"模式时拖拽完全无效，只能靠 counts 兜底）
2. **目录跑掉检测缺失**（最致命：题会静默挂到第一个课时）
3. OCR 不校验 zone 数量（question/answer 各几条）
4. 坐标无 schema 校验
5. **提交无幂等**（响应丢失后重跑会重复插入）

我们已验证有效的两道闸门（`bin/e2e_submit.py`）正好补 1 和 5 的洞：
- 识别后 `results[].question_order` 必须全等于预期
- 提交响应 `inserted` 与 order 校验 + 立即服务端回读

多书并行需先解决书源。**
