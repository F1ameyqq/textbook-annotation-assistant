## 一次修订集中处理

**R02，静态阻断。** `current_code` 的词汇共现不能证明当前 getter 参数和响应结构。为具体 getter/调用实参、endpoint、zone 及相应响应解码字段建立可复核的来源绑定；字段级引用至少说明确切资产摘要、代码位置或片段与数据流关系。不能因为注释、无关函数或同一文件出现 `success`、`ocr_result` 等词就把适用性记为已确认，或直接登记五个写死 GET。

只注册被当前证据支持的路径及参数；词汇命中本身可作为 CURRENT_CODE 观察保留，适用性保持 UNKNOWN，未知参数不试探。识别器应针对明确支持的当前代码形态实现，不要求通用 JavaScript 解释器；无法证明时诚实停止该样题后续调用，并报告具体缺失的关联。离线负例覆盖相邻注释/无关函数同词、错误参数映射、非对应响应对象和只确认部分接口；正例证明完整且一致的具体绑定。通过真实 collect 合成链验证未知 schema 不会登记或发出样题请求，也不会产出 AVAILABLE/KNOWN_EMPTY。不要扩大网络范围或用历史脚本冒充当前脚本。

**R03，静态阻断。** 对确切同一原图 bytes 执行完整像素解码，不能只用 header、size 和 `verify()` 代替。解码失败即停止，尺寸、摘要及保存 bytes 必须对应同一个成功解码的对象。增加合法原图正例及 header 可读但 JPEG 残缺的负例；不能开启全局容忍截断或重新下载。
