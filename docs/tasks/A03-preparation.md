## 3. 持久化与执行不变量

- 产物按 `artifact_id/revision/kind/content_hash` 精确引用，不覆盖旧版本；DB 记录 schema 版本。内容文件先完整写入并核验，再提交索引；孤立文件可报告，缺失/损坏的已引用文件必须阻断。测试写文件失败、事务回滚、未知 DB 版本；不静默重建一个空库继续写。
- 每次动作在效果调用之前，用一个本地事务持久化完整 intent、计划/动作摘要、目标身份、依赖版本、执行占有权及状态。事务未成功则不调用 mock；禁止把网络/效果调用包含在一个被误称为原子的本地 DB 事务中。
- 读回得到结论后先保存证据，再以事务追加 receipt/事件并更新投影视图。执行响应、目标实际状态、读回结果分别记录；成功响应不代替 APPLIED 证据，异常也不直接等于 NOT_APPLIED。
- 启动时先扫描所有已登记书的未决 intent/UNKNOWN/未提交结论，建立同书暂停，再接纳该书任何新运行。只有 intent 而无 receipt 时保留原 intent，先核对；不得通过换 run/action/question/scope 绕过。
- 同书门禁跨进程共享，书键由固定平台命名空间、目标与 book 身份构成，不含 run/scope。配置唯一状态库并校验其身份；不同本地空库不能成为支持入口的“恢复”方式。保证范围为同机、同一受控库；不宣称多机或任意外部写入者协调。
- 事务保证同书只授予一个有效执行占有权；需有进程实例身份和代次标记，效果前再次核验所有权。锁超时、PID 复用或进程消失不是未知结果已解决的证明。抢占/重启先核对；不靠删锁解暂停。其他书的离线模拟仍可独立进行。
- 去重记录至少绑定书键、精确计划引用、action_id 与动作内容摘要。同 ID 不同内容拒绝；同计划动作已受理后不能再次调用效果。换 ID 不表示新业务效果：保留内部题/片段和平台 ID 的映射，已生效目标的新计划必须重新检查，不能以印刷题号或 bbox 猜测身份。
- 图谱、政策、当前目标快照、授权或能力版本变化使相关资格失效。旧计划不可因重启被默认为 READY；正常前序动作造成的预期变化仍按 A02 规则处理。
- UNKNOWN、核对尝试、失败和解决证据追加保存；不修改旧回执的结果或删除历史。展示可更新“当前有效状态”，必须能追溯其原始未决记录和解决链。

多动作计划在中间中断时，已调用、未调用及依赖未满足动作必须分别记录。C01 现有 ExecutionReceipt 要求覆盖全部计划动作；不能为凑齐回执而在没有证据时编造结果。若未尝试动作确有完整独立 ABSENT 读回，是否允许生成 NOT_APPLIED 由正式合同明确，同时必须保留 not_attempted 的执行事实；本草案不预判尚未验收的 A02 分类规则。未完成部分先保存在 runtime 事件中，部分回执/恢复汇总的公开表达需要在派发前明确。

## 4. 核对结果与继续条件

读回必须覆盖原动作相关对象，记录快照版本、证据摘要、读回时间、比较规则版本和可归属身份。单纯数量相同、列表为空、请求失败或相同印刷题号均不足以作出结论。

| 观察分类 | 结论提案 | 后续行为 |
|---|---|---|
| MATCH：完整预期效果与原动作身份匹配 | RESOLVED_APPLIED | 记录读回平台 ID，进入后置检查；旧动作不重发。仅当该书全部未决项按批准合同解决后，才可重新检查新的工作 |
| ABSENT：范围完整且有明确未生效证据 | RESOLVED_NOT_APPLIED | 保留原动作终局与证据；重新取目标、targetcheck 和规划。**旧动作仍不可自动重发**，也不能只换 ID 克隆动作绕过重新检查 |
| CONFLICT：部分生效、重复、身份矛盾或相关事实冲突 | STILL_UNKNOWN，附冲突原因 | 保持该书暂停，形成可定位异常；不能当成 ABSENT、自动删改目标或自动覆盖。后续仅按有界核对/修正方案处理 |
| INDETERMINATE：证据缺失、不完整、无法读回或不能归属 | STILL_UNKNOWN | 保持暂停；按冻结策略有限重读，额度耗尽即报告缺口，不自动发送原动作 |

一次 MATCH/ABSENT 只解决它精确指向的 intent/action，不清除同书其他 UNKNOWN。恢复结束和新动作资格是两个步骤；在释放后又发生目标变化时，新计划仍需被拒绝。框已核对仍保持 `content_check_status=PENDING`、`submission_status=NOT_SUBMITTED`，不生成 COMPLETED。

## 5. 最小合同缺口提案（未批准、未共同确认）

已集成 [C01 类型](../../src/annotation/contracts/models.py)无 ReconciliationResult，ActionResult 仅允许 MATCH/ABSENT/INDETERMINATE；[资格校验](../../src/annotation/contracts/validation.py)对交换包中任何同书 UNKNOWN 保持阻断，BatchReport 也要求对应题和批次保持未知。只在数据库加 `resolved=true`、过滤旧 UNKNOWN 或换一个干净包都不是合法解锁。

建议在 A03 正式派发时，由主调度批准并安排唯一负责人处理以下最小扩展：

1. 新增不可变 `ReconciliationResult` 类型及公共校验/导出。沿用公共信封，精确引用原计划、action_id、持久 intent 身份及摘要；原 receipt 存在时必须引用，没有 receipt 的崩溃路径须有可校验的 intent 依据，不捏造旧回执。intent 的公开引用表示仍待合同负责人确定。
2. 每动作保留 `observation` 四分类、`resolution` 三分类、当前快照引用、读回/比较证据、规则版本及原因；MATCH/ABSENT 必须有完整证据，CONFLICT 与 INDETERMINATE 不获得写入资格。`replay_allowed` 保持 false，建议后续策略限于 POSTCHECK、RECHECK_TARGET 或 HOLD。
3. 明确解决链如何被 `assert_plan_ready` 和 BatchReport 消费：原 UNKNOWN 不变，只有精确覆盖该条未决事实的合法解决证据才能改变有效投影。缺引用、错书/范围/版本、错动作、矛盾解决记录、过期读回都拒绝或保持暂停；新 UNKNOWN 优先于旧解决记录。
4. 解除书暂停由 runtime 在事务中核对**全部 scope/run 的持久未决集合**后完成，不能由单个 ReconciliationResult 宣称整书已解锁。C01 当前交换引用限制同 book/scope，不能把跨 scope 历史硬塞进一个不合法包；单 scope 的合同证明与书级账本完整性分开验证，说明审计导出方式。
5. 补充多动作中断表达及汇总规则，避免部分执行被伪装为完整回执；明确新计划如何引用已解决的旧动作以及已生效的外部身份。旧 schema 必须明确拒绝新类型，新旧样例各自固定，提供版本/迁移和消费者影响说明。

这只是 A 侧候选方案，不能宣称 B 已确认，也不能擅自修改共同合同。合同未获准时可交付持久化、恢复分类和保持暂停的离线证据，但**完整解除暂停/恢复继续验收仍为未完成**；不能绕过公共门禁获得“通过”。

## 6. 有界故障注入与验收矩阵

每例用独立临时目录、固定输入和可重复注入点；记录执行者进程退出码、重启进程 ID、intent/事件/回执、目标独立读回和效果调用次数。至少覆盖下列场景；独立验收者另造反例，不仅复跑作者测试。

| 注入点或变体 | 必须可观察的结果 |
|---|---|
| intent 提交前退出；intent 事务写入失败 | 没有目标效果；无半条可执行 intent；重启按真实状态恢复，不冒充一次 UNKNOWN 保存 |
| intent 已提交，效果调用前退出 | 重启先暂停并读回；充分 ABSENT 后重新检查/规划，旧 action 效果调用次数仍为 0 |
| 目标已生效，响应丢失；效果后进程强制退出 | 目标状态跨进程仍存在；恢复 MATCH，效果次数为 1，无重复框 |
| 已取得读回但 receipt/索引提交前退出；本地提交失败 | 重启重新核对并幂等落记录；不得再调用效果或丢历史 |
| receipt 已提交、下一动作前退出；多动作计划中间退出 | 已终局动作不重跑；未决与未尝试区分，依赖有序，无伪造全计划回执 |
| 明确无效果；部分效果；冲突 ID；读回失败/截断 | 分别为 ABSENT、CONFLICT 或 INDETERMINATE；部分/未知不解锁、不自动重写 |
| 两个进程同时启动同书；一个持有者崩溃；过期持有者恢复 | 最多一个有效执行者；新持有者先核对，旧代次不能继续产生效果 |
| UNKNOWN 后重启、换 run/action/question/scope；另一书运行 | 同书共享暂停及完整历史；另一书无无关阻断 |
| 同书两个未决项，只解决一个；重复核对/重复落盘 | 不提前整书解锁；同一证明不会重复生效，事件可追溯 |
| 同 ID 改摘要、旧图谱/政策/快照、同题重规划 | 内容冲突和过期资格阻断；新 ID 不成为重复效果许可 |
| 产物缺失/哈希损坏、DB 版本未知、状态目录被误换 | 拒绝执行并说明修复条件，不自动空库启动或忽略校验 |
| 核对期间目标变化、恢复结论与当前目标矛盾 | 保留证据并重查；拒绝过期结论解锁/执行 |
| 异常、跳过、未入图谱题；已保存但内容不可读 | 固定 scope_manifest 分母完整，内容 PENDING，提交 NOT_SUBMITTED |

首轮核对上限建议冻结为“每个未决动作最多 3 次只读尝试”，并设置有限等待；到限终止本次恢复，保留暂停和下次恢复条件。没有无限守护轮询、无限重试或任何旧保存自动重发。进程强制退出测试只终止该用例自己启动的子进程，不操作用户浏览器/服务；此测试证明进程崩溃恢复，不宣称断电或存储硬件故障保证。

交付需有最短运行/故障注入/重启/查询命令、实际报告与确切提交；包含正常路径、已生效响应丢失、明确未生效三条独立进程演示，以及上述关键拒绝路径。独立验收和主调度复现通过、完成受影响检查后才记录 ACCEPTED/INTEGRATED；自报写完只进入 REVIEW。

## 7. A03 与 I01 的分界

A03 以已接受 A02 固定输入为边界，交付持久状态与恢复公共入口、追加证据、最小异常查询和模拟故障证明；不实现识别、复杂工作台、完整 patch 冲突迁移或真实 executor。A03 的统计只保留真实范围和未决状态，不代替质量判断。

I01 的 A 侧工作接入 A01 来源与 A02/A03 接口，使用明确标记的 B 合同桩，演示正常、可修正异常、未知保存恢复三条完整离线路径，并核对跨模块版本/范围/资产搬运。接入真实 B 产物另记兼容性与双方联调结果；不把桩 PASS 当成 B 验收。A04 不阻塞离线 I01，真实平台恢复仍需后续既定路线中的具体范围和证据。

合并顺序由主调度固定：先冻结并验收 A02 原合同版本，再以确切 A02 提交评估恢复合同改动，安排唯一合同写入者并回归 C01 旧样例和 A02 消费接口，最后记录 A03 采用的新基线。不能在 A02 独立验收途中替换其合同，或把新版本的兼容性未经复验地算进旧验收；公共变更仍在 A03 依赖协调范围内，不另行扩张路线。

派发前剩余事项：固定 A02 接受提交及其公开接口；决定恢复合同最小扩展和唯一写入者；固定同书键/状态库规则、部分计划表达、故障注入点与重读上限。未决项必须出现在正式任务单和验收条件中，不能留给执行者通过放宽门禁自行解决。
