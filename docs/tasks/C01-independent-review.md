# C01 独立验收

验收 [C01 合同实现](C01-contracts-implementation.md)，执行对话 ID 和 worktree 路径由调度状态 `docs/coordination-state.json` 提供。先核对任务要求和原设计；正式验证等待执行完成、确切提交和交付报告齐备后再进行。任务状态及完成通知用 wait_threads 紧凑查询，不频繁重复读取整段对话。

验收者不改实现、不启动平台浏览器、不调用付费模型、不读取凭据或管理 B；在 `.local/stages/C01-review/` 生成独立测试输入，将报告和验证证据写到主项目 `docs/tasks/C01-review-report.md`、`docs/evidence/C01/review/`。对执行者 worktree 只读；测试产生的临时资源放自己的工作目录。

核对精确提交及范围，复现提供的检查；另外构造能区分错误实现的失败输入，验证引用、原图几何、版本/摘要、两份 PASS、UNKNOWN、CONTENT_PENDING、提交状态、patch 基线和相对资源路径等要求。复制完整样例到另一个目录、通过公开 API/命令行消费，不能依赖原作者 cwd 或个人绝对路径。核对运行环境 Python 3.9.13 和实际依赖，区分合同桩与真实平台结果。

检查 normal/exception/unknown 三组完整产物是否覆盖类型并彼此引用一致；检查摘要规则是否可复现、字段是否只有一个权威来源、通用语义是否错误耦合平台题序/角色。业务歧义应保持显式未决；A 内部实现通过不能表述为 B 已接受。

交付逐项通过/失败/未测及精确命令、错误输出摘要、被验提交和文件摘要。结论 ACCEPTED / REWORK / BLOCKED；若失败给出最小复现和修复要求，不替实现者修代码来制造通过。最终本地集成与下游释放由主调度负责。不得将 C01 通过宣称为平台保存、识别准确率、自动恢复或完整产品通过。
