用途：与技术搭档讨论实现方案、实验顺序和工作边界  
当前归档根目录：`D:\1800`

本文汇总需求材料、人工演示视频、网页实际体验、正常页面读取结果及本地样本核查。文中分别标明已验证事实、源码线索和技术建议；建议方案尚未实现，也没有自动标注成品通过平台验收。

早期的《项目交接说明》保留了完整需求和初次调查记录。本稿补充后续 MCP 接入、浏览体验、原图获取及样本关联结果；旧说明中“尚未翻页”“只有早期 CDP 核查”等状态，应以本稿的新证据为准。

## 1. 先看当前结论

1. **交付目标是自动框选、配答，最后由人工确认提交。** 当前不是完整无人值守系统，自动提交也不是已承诺的交付内容。开发收费已确定为 1800 元，应控制首版开发和后续适配的投入。
2. **浏览器接入和主要浏览动作已经打通。** 能读取控件、翻页、定位已有题、查看预览、缩放和平移；这不代表新建框和保存链路已经验证。
3. **已经拿到完整原图，不必把当前屏幕截图作为唯一识别输入。** 现有本地材料足以启动离线识别原型和小规模模型对比。
4. **当前样本是 14 道既有平台结果、36 个历史框、4 张原图。** 已把题目内容、目录、题答页码和原图坐标关联起来，但它们还不是独立核准的验收标准。
5. **主要难点已转为切题、题答匹配、跨页完整性和可靠画框。** 不是单纯“让模型能看到网页”。
6. **推荐优先验证“原图采集＋本地 OCR/版面候选＋按量视觉模型＋确定性执行”。** 模型负责内容理解，固定程序负责浏览器操作和状态核对。
7. **尚无新模型效果、速度和费用实测。** 本次付费模型调用为 0；平台已有 OCR 任务的成功状态不能替代这项测试。

## 2. 已有需求与材料边界

### 2.1 已明确的方向

- 业务对象是题目与答案分离排版的教辅书籍。
- 需要识别题干、选项、答案和解析，保留题号及目录归属，并支持图片、表格等内容类型。
- **跨页续标和组合题已经在原始需求内，不能因首批样本未覆盖就默认删去。**
- 普通选择题的选项、组合题公共材料及小题、同排多题答案，需要按不同业务规则处理。
- 公式按文字内容处理，后续检查 LaTeX、源文和最终显示是否一致。
- 最终由人检查并提交，程序应能清楚呈现候选框、题答对应和不确定项。

### 2.2 不再作为前置阻塞的材料

- 文件夹内的视频已演示基本人工操作流程，应直接作为流程依据，不需要重新要求录一遍基础演示。
- 支持范围可以随几本样书的实际录入逐步完善。当前先建立可回归的样本和规则记录，之后增加版式，不必在原型前穷举全部书籍。
- 仍需补证的是视频和当前样本没有证明的特殊环节，例如同题跨页、多片段关联、保存及撤销效果。

### 2.3 仍存在一个明确的业务冲突

原始需求文档要求普通选择题**每个选项独立一个 W 框**，但视频及当前 5 道选择题都是**一个 W 框容纳 4 个选项**。两者不能同时作为唯一验收标准。

目前以明确的文字需求为基线，最终口径需要确认。数据结构可以兼容两种粒度，但现有合框样本不能直接用来评判“独立选项框”方案的准确率。

### 3.1 浏览器接入

当前机器使用 Edge 已登录会话，通过 Microsoft Playwright Extension 连接 Playwright MCP。MCP 包固定为 `@playwright/mcp@0.0.83`，启用了 `vision` 坐标工具和快照边界框。

开发环境已验证的关键启动参数为：

```text
--extension --browser msedge --profile-dir-name Default
--caps vision --snapshot-boxes --file-paths absolute
```

这里的 `Default` 是当前机器的浏览器配置目录名称，对方环境应核对自己的目录。连接当前浏览器需要用户在扩展中选择目标标签页；不需要共享账号密码、Cookie 或浏览器配置目录。

官方能力说明见 [Playwright MCP](https://github.com/microsoft/playwright-mcp) 和 [Vision mode](https://github.com/microsoft/playwright.dev/blob/main/mcp/vision-mode.mdx)。本项目的实际接入结果以本地回执为准。

### 3.2 浏览操作与实际陷阱

| 交互 | 已观察结果 | 对程序实现的影响 |
| --- | --- | --- |
| 目录折叠、展开、整栏收起/展开 | 能正常浏览 | 展开状态不等于目录数据被修改 |
| 两侧页码输入、上一页/下一页 | 可以分别操作 | 题目页和答案页是独立状态 |
| 已完成题号定位 | 会定位相关页面并展开目录 | 不等于当前正在编辑该题 |
| 编辑/预览页签 | 能切换 | 非编辑态的预览仍可能是当前新题，不能当作所选历史题的内容 |
| 滚轮 | 在画布上缩放，以指针附近为锚 | 需要同时记录缩放和平移 |
| 重置缩放 | 恢复整图适配 | 宽答案图会变得很小 |
| 放大上限 | 实测达到源码中的用户倍率上限 5 | 继续滚轮不会无限变大 |
| 空格＋左键拖动 | 已验证只做画布平移 | 按下和释放空格应成对处理 |
| 中键落在已有框上 | 曾意外进入第 12 题编辑视图 | 不能把中键拖动视为在任何位置都安全的平移方式 |
| A/W 快捷键 | 工具栏及缓存处理逻辑为 A＝答案、W＝选项，提示文案有反向情况 | 应核对实际功能和读回结果，不能只照 tooltip |

中键误触后已点击“退出编辑”，恢复新题 15 及原浏览位置，没有输入内容、保存或提交。这一现象表明，已有框上的交互可能覆盖画布平移，不能仅凭空白画布支持中键平移来判断安全。

实际操作中还遇到浏览器页面为 `hidden` 时常规定位点击等待超时的情况。后续需要测试窗口可见性、重绘及超时的处理；不能依赖反复盲点按钮解决问题。

程序至少要分别维护：当前目录选择、已完成题的浏览题序、当前编辑题、新题状态、左右页码及两侧视图变换。

### 4.4 题号、目录与页码的关键区别

当前样本可按书籍 ID＋导出 `tixu`／标注 `order_in_level` 关联 14 道题，目录 ID 也能逐题对应。**这只验证了当前样本，不意味着所有书的题序规则完全相同。**

最重要的反例是：平台题序 **14** 对应新课时的印刷题号 **1**，位于查看器第 10 页、纸面第 6 页，目录为“第1章／1.2 一元二次方程的解法／第1课时 直接开平方法”。

因此，题答匹配应至少同时保存书籍、目录路径、印刷题号、平台题序、来源页和子题编号。不能在全书范围仅凭数字 `1` 查找答案，也不能把资源文件名里的零基索引当查看器页码。

### 5.1 内容导出能提供什么

用户下载的 `46006966_paper_questions.jsonl` 为 7809 字节、14 条记录，每行一题。

| 类型标记 | 数量 |
| --- | --- |
| `xuanze` | 5 |
| `tiankong` | 5 |
| `zuhe` | 3 |
| `wenda` | 1 |

主要字段包括 `tixu`、`tihao`、`question`、`option`、`answer`、`analysis`、`tishi`。14 条题干和答案均非空；5 道选择题各有 4 个 option；仅第 10 题的独立 `analysis` 字段非空。公式以 LaTeX 字符串保存，第 5、6 题的图形通过 HTML `<img>` 链接引用。

`tihao` 及本文件中的书籍/试卷元数据字段为空。JSONL 本身没有标注框坐标、完整目录归属和完整页图；这些是通过后续读取另行补齐的。

### 5.2 标注框构成

| 角色 | 数量 | 备注 |
| --- | --- | --- |
| `question` | 16 | 包括 14 个文字题干框和 2 个图片题干框 |
| `choice` | 5 | 当前每道选择题只有 1 个选项组框 |
| `answer` | 14 | 每题都有对应答案框 |
| `analysis` | 1 | 第 10 题 |
| 合计 | 36 | 34 个 text，2 个 image |

第 5、6 题导出内容中的图片链接与相应 image 框的 `image_path` 一致。题 6、11、12 是组合题，小问和答案在导出中合为长字符串，并没有独立子题对象。解题过程也可能保存在 `answer` 字段，不能因为 `analysis` 为空就判定漏录。

### 5.3 已发现的参考数据问题

| 问题 | 具体证据 | 对评测的影响 |
| --- | --- | --- |
| 第 3 题题干框轻微越界 | 原图宽 1178，框 `x2=1181.094…`，右超约 3.09 px | 不能不经复核就作为严格坐标真值 |
| 第 10 题解析框跨入第 11 题答案 | 两框交集约占第 11 题答案框面积的 91.08%；原图复核也看到解析框纵向范围延伸进下一题 | 文本导出正确不等于框范围正确 |
| 第 8 题 HTML 残留 | 题干有孤立 `</span>` | 输出仍需保留原值并另做清洗/渲染检查 |
| 选项标注粒度冲突 | 当前 5 个 W 框分别容纳 4 个导出选项 | 历史框与最终业务规则可能不同 |
| 验证标记未明确 | 36 条 `verified` 均为 0，字段业务含义未确认 | 不能声称这些数据已经平台验收 |

本次没有修正网站数据，也没有覆盖原始导出。核查意见单独保存。

**当前 14 题应定位为“已有结果参考＋回归素材”。** 先逐题核对原文、框范围和题答归属，再挑选独立验收样本。已有答案和正确框不能作为模型盲测的输入，否则会把复制参考结果误当识别成功。

当前样本覆盖了部分公式、组合题和图片题，但**没有同题跨页实例，也没有表格和七选五实例**；这些随后续样书逐步加入，不能写成已验证或默认不支持。

## 6. 整套结构化导出的现状

页面真实菜单名称是 **“更多操作 → 导出整套书籍JSON”**，不同于“导出试卷试题”。

已实际点击，平台先发起 `POST /qieti/api/annotate_ocr/structured-upload/precheck/46006966`。虽然外层返回 `code=0`，但业务字段 `data.passed=false`，错误为书籍信息中 **province=山东省、city=苏州市不匹配**。

结果是：**没有下载到平台的整套结构化 ZIP**。提示已关闭，没有修改书籍元数据，也没有绕过导出阻断。另几个结构化导出入口在缓存前端代码中共用预检，不值得反复触发同一失败。

原图、目录及历史框已经从正常页面读取取得，因此这个导出问题没有阻止本次样本整理。若后续要使用该导出功能，需要由负责书籍信息的人核对正确元数据，再按平台正常流程处理，不能凭猜测替换省市。

## 7. 建议技术路线

### 7.1 总体分工

```mermaid
flowchart LR
    A["完整原图＋目录"] --> B["分栏、OCR、版面候选"]
    B --> C["视觉模型：角色判断与题答配对"]
    C --> D["原图坐标计划＋完整性检查"]
    D --> E["离线覆盖图与人工复核"]
    E --> F["受控浏览器画框＋读回"]
    F --> G["人工最终确认提交"]
```

这是建议的系统结构，不是已经打通的自动流程。核心思路是把识别、业务归并、浏览器执行分开，便于替换模型、复测和统计成本。

### 7.2 优先试验的三条路线

| 路线 | 方法 | 适合先验证的内容 | 主要待解问题 |
| --- | --- | --- | --- |
| A：本地候选＋视觉模型，优先建议 | 本地 OCR/版面给出文字行和图块，模型对候选区域做角色、组合题和题答关系判断 | 减少模型直接猜像素边界，复用同页识别结果 | OCR 对公式/密集答案的质量、候选合并、栏间续接 |
| B：视觉模型直接输出候选框 | 原图裁片直接生成结构化候选框，再用 OCR/规则检查边界 | 快速建立对照基线，判断模型理解能力 | 坐标偏差、漏小字、输入缩放、输出长度和费用 |
| C：本地 OCR＋固定版式规则 | 对稳定样书用题号、行距、栏界及目录规则切分 | 探索减少按量调用的空间 | 新书排版适配、组合题和复杂答案泛化 |

先在相同原图和评价口径下比较 A/B，不应预先宣称哪条最便宜或最准确。通用视觉 Agent 可以继续辅助开发探索和少量异常处理；固定的翻页、缩放和平移优先写成可核对的程序动作。

### 7.4 原图、裁片和屏幕坐标必须分层

建议以**原图像素**作为所有候选框的主坐标空间。答案图先按内容分栏，必要时纵向分块；各裁片记录原图偏移、缩放及补边信息。

在没有补边的简单情况下，裁片左上角为 `(x0,y0)`，模型输入相对裁片的横纵缩放为 `sx,sy`，模型输入坐标 `(u,v)` 回投为：

```text
x_original = x0 + u / sx
y_original = y0 + v / sy
```

若有补边，应先减去补边偏移；若模型返回 0～1 归一化坐标，应先还原到模型输入尺寸。重叠裁片必须在原图坐标中去重，不能把同一道题的续片或相邻栏误合并。

浏览器画框是另一套映射：

```text
client_point = canvas_client_origin + current_offset + current_scale * original_point
```

`current_offset` 包括当前适配、居中和平移造成的偏移；`current_scale` 来自当前页面实际变换。不能把早期坐标拟合的固定数值用于后续所有视图，也不能将设备像素比重复乘进 CSS client 坐标。

已有历史框与显示边界曾做过小残差拟合，但这只证明当时的显示几何关系。**新建框是否吸附、拖动终点如何处理、读回 bbox 是否一致，仍需实测。**

### 7.5 中间结构和执行层

一题应支持多个物理片段，而不是强制“一题一个矩形”。建议至少保留：

| 信息 | 建议字段或内容 |
| --- | --- |
| 题目身份 | 书籍、目录路径、印刷题号、平台题序、逻辑题 ID |
| 来源 | 查看器页码、资源索引、图像尺寸/哈希、裁片偏移 |
| 物理片段 | 原图 bbox、Q/W/A/E 角色、text/image/table 类型、阅读顺序 |
| 逻辑关系 | 组合题公共材料、小题、逻辑选项与跨页片段关联 |
| 内容 | 原始文本、公式/图片引用、处理版本 |
| 异常 | 缺答案、重号、越界、疑似跨页未完、配对多解等 |
| 执行回执 | 计划框、实际新增框及读回差异、当前题目状态 |
| 调用记录 | 模型/配置版本、usage、费用、重试与缓存命中 |

状态可从“候选生成→待人工复核/可执行→已画框待人工提交”推进。跨页未完、归属不明或题答有多个候选时保留未就绪状态，不能自动补造缺失内容，也不能把“已生成 JSON”当作业务完成。

当前读取接口可辅助采集，但写接口没有验证。首轮线上验证应沿可观察的单题操作进行，核对绘制、角色、类型、题序、取消及读回；不把内部写请求当作已经可用的捷径。

创建框或保存后若结果不明，先停止该题后续写入，重新读取并核对实际状态；确认哪些动作已经成功后，再决定继续还是交给人工处理，不直接重发整题操作。

### 7.6 平台 OCR 的复用位置

平台已有 14 条 `SUCCESS` OCR 任务，并能读取其中的已有识别文本。这说明平台存在识别能力，但**新题的调用条件、效果、费用、是否支持所需批量方式均未测试**。

可以评估让外部模型主要做定位、角色与配答，文字识别尽量复用平台流程；也可以保留独立 OCR 路线进行对照。复用平台 OCR 是待验证分支，不是当前架构的必要前提。已有任务时间和成功状态不能用于推算新方案的单题成本。

## 8. 成本和效果应怎样实测

为了把费用归因到图片、题目和重试，实验优先使用可记录 usage/账单的按量调用。桌面助手和订阅适合探索，但不能拿当前探索过程直接推算客户生产运行成本。

每次实验记录：模型具体版本及计费区域、输入图片/裁片和尺寸、提示版本、输出、输入/输出及其他计费项、耗时、重试原因、升级模型、缓存命中、人工修改量。价格以测试时官方实际计费口径核对，本稿不把此前讨论过的单价写成已实测成本。

```text
每道验收通过题的模型费用
= 全部识别、重试、升级及复核调用费用 / 最终人工验收通过题数
```

同时报告每千题模型费用、首次处理与缓存处理成本、每题人工修正时间、总耗时和失败率。本地推理资源及维护投入另列；本地 OCR 没有按 token 账单，也不等于没有运行成本。

评测至少覆盖：漏题/重题、题干/选项完整性、答案和解析归属、目录与题号重置、图表和公式保真、跨页完整性、需要人工修正的比例。IoU、JSON 可解析率或调用成功率均不能单独代表题目处理成功。

当前 14 题可以用于开发摸底。经人工核对后划分开发与验证用途，后续样书保留新增验证样本；用于调参的题目不能同时被当成独立验收成绩。

效果评测的覆盖率、失败率以预先约定的全部测试题为分母，跳过题仍计入失败或待处理统计。单位成功成本的分母仍是最终人工验收通过题数，失败和跳过所产生的费用计入分子。若通过题数为 0，只报告本批花费及失败情况，不报告每道成功题的费用。

成本控制首先尝试：同页/同栏共享识别、图像哈希和配置缓存、OCR 后按需调用、低价模型到高能力模型的有限升级、限制重试。答案图即使只处理一栏，也要计算实际 API 图片计费和输出长度，不能简单按截图张数估算。

## 10. 建议的推进顺序

1. **整理参考样本。** 从现有 14 题开始逐题复核，把现存错误和业务冲突显式标注；同步保留视频及原始需求。
2. **做离线原型。** 完成“原图→分栏/OCR/候选区域→角色与配答→原图坐标→覆盖图”，先不接网页写入。
3. **做小规模模型与成本对比。** 固定同批输入、业务规则和评价口径，对比候选路线，报告人工修正量及总费用。
4. **做单题线上闭环。** 在另行指定的测试范围内验证新框、读回、取消、吸附及角色/类型；确认实际保存语义之后再扩大。
5. **随几本样书扩展。** 优先增加题号重置、复杂答案、组合和跨页，保留独立验证样本；避免只适配当前第一页。
6. **再做小批运行和交付。** 补齐状态记录、重复执行防护、异常待处理队列、人工确认入口和部署说明。

当前线上授权仍是浏览和读取，不包含改目录、改内容、创建新框或提交。文档及参考源码不构成扩大线上操作范围的授权。最终由人工提交的成功结果，应通过平台反馈及必要的重新读取确认。
