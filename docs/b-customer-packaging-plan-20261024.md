# 无 agent 客户的 B 侧产品封装方案

2026-10-24。用户要求完成当前“一定是直角三角形吗”课时后停止扩章，并考虑封装给没有agent的客户。用户已明确确认：**客户使用Windows，可以联网识别。** 因此首版采用Windows本地客户端加联网识别服务，项目保存、查看、人工校对和导出留在本机。本文是基于现有代码的实施方案，不是已完成的安装包或新的开发承诺。

## 客户收到什么

当前内容包已经有一个可直接使用的只读入口：解压本批ZIP后用浏览器打开`index.html`，可看原图、转写和答案，无需agent或Python。主会话检查该HTML含70个本地图片引用，缺失资源0、远程资源0、脚本0；它没有输入框或编辑按钮，因此只能用于查看，不能宣称客户已能独立识别和校对导出。

建议第一版是一个可双击启动的本地应用：启动后自动打开工作台，客户可以导入书页、运行识别、对照原图校对、保存项目并导出内容包。客户不安装Codex、Python或Git，不编辑JSON，不执行命令，也不管理agent会话。内部继续使用现有C01交付和来源校验，界面显示“待校对”“缺少答案页”“检查通过”等具体状态。

客户路径为：新建项目 → 导入题页及答案页 → 查看本批页数及识别费用提示 → 联网识别候选 → 对照原图核对题干/选项/图/公式/配答 → 导出并重新打开验证。优先支持已有图片输入；PDF导入需另接逐页渲染、页序和尺寸校验，不能把当前图片导入能力写成已支持PDF。

产品闭环以B侧可用内容包为终点。平台写入接入另由A适配，当前包内PRE_APPLY的政策/平台目标提示不直接变成客户的笼统红色错误；B内容缺陷与A未执行分开显示。

## 已有能力和实际缺口

| 环节 | 已有实现 | 客户版需要补齐 |
|---|---|---|
| 导入、框选、保存 | `tools/prebox_b.py`及`src/annotation/prebox/`有本机图片导入、几何候选、框编辑、草稿历史和JSON导出 | 双击启动、项目选择、自动保存、故障恢复；现有界面仅编辑草稿框 |
| 本地识别 | `tools/run_source_region_ocr.py`可调用已安装的RapidOCR/ONNX并保留原始观察 | 随包模型/运行库、模型缺失诊断；目前输入需已声明区域和平台来源证据，不能直接处理任意客户资料 |
| 客户资料来源 | 已有平台原始来源和摘要校验 | 新增本地图片/PDF来源类型，自动生成本地来源清单；保留原平台校验，不伪造业务响应填满旧字段 |
| 组题和配答 | `tools/project_section_source_c01_b.py`把完整来源规格投影成可消费内容 | 当前完整转写、跨栏分段、题图归属、配答、公式纠错大量依靠agent看图；需候选提取及客户可操作的语义校对界面 |
| 内容审核 | 原图裁片、字段差量、独立内容预期和故障样例 | 客户可编辑题干/选项/答案、调整顺序与题图、确认配答；编辑后生成新修订和相应校验，不覆盖原OCR |
| 导出和读回 | `tools/export_lesson_c01_b.py`、`verify_lesson_c01_b.py`及固定A24完整消费已可重复运行 | 串成项目内任务，自动生成ZIP、预览和检查报告，再用新进程验证导出；不要求客户手填SHA |
| 启动与更新 | 当前主要是命令行与开发环境 | 自带运行时的发行构建、版本固定、离线启动、升级保留项目、可导出的错误日志 |

本课时通过证明的是固定输入的内容交付。任意新书的完整无人值守识别尚无充分证据。第一版保留人工校对：原图与文本并排，缺答、重复选项、漏图、题空污染和不确定配对应进入具体问题队列。

## 建议技术路线

复用Python处理逻辑和本地网页界面，由单一启动程序管理仅监听127.0.0.1的本地服务、后台识别进程及工作目录。第一版无需额外重建前端技术栈。只读资源放应用目录；原图、用户编辑和进度放用户项目目录，避免随升级覆盖。

Windows发行优先验证PyInstaller的onedir形式，将Python、依赖、静态界面和必要数据文件一同收集，再提供启动入口；选择本地OCR预处理时再携带相应模型。官方说明该形式可让用户无需安装Python，同时较易诊断依赖收集问题；单文件形式会在启动时解包，宜在目录版验证后考虑。[PyInstaller打包模式](https://pyinstaller.org/en/stable/operating-mode.html)

必须检查动态导入、模型文件、HTML/CSS/JS、合同schema和字体等资源。现有重放工具有`sys.executable`启动Python脚本的方式；冻结后的`sys.executable`指向应用自身，需要明确worker子命令或随包解释器，不能原样当系统Python调用。[运行时路径与可执行文件说明](https://pyinstaller.org/en/stable/runtime-information.html)

联网识别作为首版识别主路径：客户端管理本地项目、上传范围、任务进度和校对；识别服务将题干、选项、题图、公式和答案候选连同来源页/区域返回，客户端保留原始结果和后续修订。服务端按任务ID记录结果，避免客户端重开或重复点击造成同一任务重复计费。应用与模型服务之间使用明确接口，客户不安装或操作agent。

建议由受控后端管理模型服务密钥和用量，客户端只持有应用访问凭据，不内嵌开发者模型密钥。批次开始前提示要发送的题页/答案页、页数和可获得的费用估计，设置用量上限；未确定价格时明确显示未估算。请求超时或断网保留项目和已返回结果，恢复后由用户重试未完成项，不无限自动重试。具体模型、价格及服务部署待选型实测，本轮没有开通服务或发起付费识别。

断网仍应能查看已有结果、校对、保存和导出；新一轮联网识别标为待连接，不把缓存缺失当成功。本地RapidOCR可复用为预处理或后续离线补充，但完整离线识别不作为此次已确认的客户版首发要求。联网模型输出仍是候选，人工校对和内容检查保留。

## 落地顺序及验收

1. **打开已完成内容包。** 将本课时16题作为固定样例，客户可双击启动、看原图与内容、查看具体问题、关闭后重开。先证明无开发环境也能运行。
2. **客户独立完成一课时。** 增加本地来源导入、联网识别任务、文本/公式/配答校对和导出按钮。必须从客户导入的文件开始，不预先用agent写好source-spec再假装自动完成。导出的新修订经完整读回且保留原始材料。
3. **形成可交付发行版。** 在没有Codex/Python/Git的干净Windows用户环境验证；覆盖中文/空格路径、无GPU、联网识别、断网后校对保存及恢复任务、工作中关闭重开、重复点击不重复收费、单题失败可重试、缺答案页和导出资源缺失。发布版本、服务模型版本及依赖固定，项目与程序升级分离。

这一轮完成课时包后先停，不立即开发安装器、接付费模型或启动整章扩展。下一轮先实现第1步及贯通第2步所需的最小入口，再按实际样例决定是否扩展批量识别。
