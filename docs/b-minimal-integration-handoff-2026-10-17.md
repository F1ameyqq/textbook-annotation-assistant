## 3. 需要共同对齐的接口

首轮建议保留 B 内部格式，由双方先确认映射，A 实现有界接收适配；B 也可提出在出口转换为公共格式。选定方案和确切版本后记录，不要求双方重写内部流水线。

| 对齐项 | 目前差异/风险 | 需要确认的内容 |
|---|---|---|
| 入口层级和版本 | B 有 stage wrapper，实际结果在 `payload.result`；G07/Check07 为 trial 0.7，A 公共版本另有定义 | 每种文件入口是什么、wrapper与结果分别如何识别；支持版本白名单，未知版拒绝 |

| 两类摘要 | 文件 SHA256 与规范化 JSON 的 content_hash用途不同 | 各格式具体的规范化/计算范围及实现入口；保留原始身份，适配后新产物重新绑定来源 |
| 来源和范围 | viewer、resource、印刷页号、资产 ID、章节身份各不相同 | 坐标绑定原图 ID/尺寸/SHA；未知页映射显式保留 UNKNOWN；同为173的不同资产不能合并 |
| 内容与区域 | 原始 `fragments` 不是最终框；G07 的活动内容和 typed regions 与旧格式有差别 | `content_fragments`、`render_regions`、来源区域和内容类型的消费规则；不能每 OCR 片段画一框 |
| 新区域与字符跨度 | REGION_DRAFT 可没有旧 source_fragment_ids；B 字符区间按 Unicode 码点、左闭右开 | 以有效 source_region 追溯新块；前端不得直接使用 JavaScript UTF-16 下标解释码点跨度 |
| 题、答案和共享材料身份 | 印刷题号或平台顺序不能充当内部全局 ID | 稳定内部 ID、章节/组别命名空间、题答关联和跨页顺序；未归属来源不得按同号猜配 |
| 质检与执行资格 | B 的 DONE/READY/来源一致性通过不等于内容正确；A planner依赖具体 PRE_APPLY/TARGET 与当前输入 | 当前问题如何映射且不丢失；HOLD阻止执行；更新图谱/来源后旧检查失效；未核准内容不可转换为PASS |
| 修订与回滚 | 活动内容会更新，原始观察和旧版本须保留 | patch绑定哪个版本，哪些引用/检查需重算，陈旧计划如何拒绝；不依赖B本机工作区head |

## 6. 首轮联调步骤和完成标准

1. **冻结交接输入。** B 给出确切代码SHA、包/清单摘要和三类样例；双方记录 A 消费者版本、支持格式和待拒绝的字段/版本。
2. **先核验包。** A 在独立目录核对文件与对象摘要、引用闭包、来源完整解码、范围和身份；缺失项逐项回报，不从评估摘要重造对象。
3. **实现并检查最小映射。** 在双方确认的格式内读取活动内容/区域/问题。任何尚不能无损表达的语义显式报不支持，不丢字段后假装兼容。
4. **验证分流和拒绝。** 真实候选保持HOLD；歧义可定位；陈旧检查、未知版本及坏资源被明确拒绝。结果变化时旧检查不得继续有效。
5. **验证模拟对照。** A现有全合成正常路径产生模拟回执，UNKNOWN对照暂停；与真实B草稿接收结果分开归档。本轮不证明A03跨进程恢复或真实平台成功。
6. **回传最小接收记录。** A提供双方SHA、包摘要、命令、退出码、成功/失败/未支持、输入输出引用及问题路径。B确认字段解释后，再选择下一小批真实内容和整章来源补充范围。

首轮完成意味着：**另一台机器能读取同一个完整包，能解释当前候选并正确保留HOLD，能拒绝明确错误的输入，且双方清楚下一处接口缺口。** 它不等于识别准确率达标、章节完成、跨进程恢复通过、线上录入成功或整个项目交付。
