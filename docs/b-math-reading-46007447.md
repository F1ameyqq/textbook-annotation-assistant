## 实际补读与保留的信息

`math_reading.py`从已验证二维布局和固定原裁片读取每个分式的分子、分母，包括已有OCR的角色。当前Q16共有11个分式、22个角色；每个角色固定两种预处理，最终缓存含44次实际RapidOCR CPU调用。记录原裁片、角色裁片、RGB/BGR像素、缩放变换、全部原始结果/耗时、候选引用、模型和依赖摘要。默认重放不导入OCR引擎或访问网络；注入测试后端始终标为SYNTHETIC_TEST，不能冒充CPU执行。

旧布局中9个分子和2个分母没有OCR；新角色观察均有候选，但不会覆盖旧17个OCR元素、原遗漏账本或图谱。22个角色中19组两次文本一致、3组分歧。一致仅是观察，不是公式正确率。

实际反例：最后一个分子的两次结果都是`a+1`，原图上方仍有淡色字墨；独立目视开发观察为`a²+1`。源像素高位风险与补读槽继续保留，不能因一致而清除。另一次隔离小字探索仍误读，未据此补写符号。

风险扫描保留两像素上下文中的完整连通组件。原布局紧框本身会截掉高位字上半部，因此补读槽不能直接沿用紧框。生产者多阈值保守记录26个组件、涉及13角色；独立检查在210阈值发现12个完整高位组件、涉及10角色，全部由生产者风险覆盖。这些是不同方法的局部风险观察，不是准确上标数量；普通字符、淡色断笔与邻近墨迹仍可能产生误报。无风险也不证明转写完整。

## 独立质量检查

`math_reading_quality.py`不导入或重跑生产者生成预期。它核对输入版本、所有角色及候选、原始引擎数据、源像素与变换、二维顺序、风险及补读槽。完整组件见证必须对应实际阈值连通组件；修改候选却不改原始CPU回执、丢角色、重复ID、重写缩放、删除风险，或协调重算摘要后裁掉上标上半部，都有失败回归。

`accepted=true`只表示所给来源和候选保持一致。文字与数学语义不因此通过，也没有人工业务验收。识别器、检查器共享固定布局和原图，独立性限于检查逻辑与额外像素观察，不声称获得两个独立识别模型的确认。

开发对照`tests/fixtures/book46007447/math-reading-source-review.json`在直接查看完整源裁片后记录22角色的目视观察，明确MODEL_VISUAL、非人工金标。识别器和质量检查不读取这些预期；对照不能替代留出集或业务准确率。


```sh
python tools/verify_identity_review_b.py --source SOURCE/source.json
```
