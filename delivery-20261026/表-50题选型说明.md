# 首批 50 题选型说明

2026-10-26。数据源：`wholebook-source.sqlite` 的 `pairing_status`（1303 行，只读）。
生成脚本：`select_pilot.py`；机器可读：`selection.json`；逐题表：`表-50题选型.csv`。

## 一、为什么不是"随便挑 50 道"

用户要求这 50 题覆盖 **普通选择题、图形题、公式题、跨页题、同号题**，并且要能"得到实际处理速度和剩余异常类型"。
所以选型必须满足两条：

1. **覆盖五类**——每类都有，不能全是简单题；
2. **权重贴近真实工作量**——435/529 的待审校负担集中在「答案定位 / 题号标记」，如果 50 题里这一类占比很低，测出的速率会系统性偏乐观。

## 二、五类在全书 1303 个实例中的实际规模

| 类型 | 实例数 | 说明 |
|---|---|---|
| 普通题（READY_TO_PAIR 且无异常） | 754 | 机器已能唯一配对 |
| **答案定位 / 题号标记** | **435** | 529 待审校中的主力，用户点名的 428 项同类 |
| 公式题 | 63 | 含 `MATH_OR_UNCLEAR_ANCHOR_REVIEW` 或 `UNSPLIT_NUMERIC_CHAIN_REVIEW` |
| 其他异常 | 36 | 来源区域恢复、答案块上下文等 |
| 图形题 | 31 | 含选项图形区、题干插图或 `GRAPHIC_OPTIONS_REQUIRE_REVIEW` |
| 同号题 | 29 | `DUPLICATE_QUESTION_IDENTITY` 或 `VARIANT` |
| 跨页题 | 23 | 题干片段跨 ≥2 页 |

注意：类型之间有重叠（一题可能既跨页又要定位答案），所以合计 > 1303。

## 三、50 题的分配

| 类型 | 配额 | 为什么这个数 |
|---|---|---|
| 答案定位 / 题号标记 | 22 | 全书最大的异常类别，必须占最大权重才测得准 |
| 图形题 | 8 | 全书 31 例，8 例足够测出图形类均速 |
| 普通题 | 5 | 作为基线对照，验证"顺利路径"有多快 |
| 公式题 | 5 | 63 例中的代表 |
| 跨页题 | 5 | 全书仅 23 例，5 例已达 22% |
| 同号题 | 5 | 29 例中的代表，含变式 |

## 四、分布校验

- 覆盖 **27 个不同课时**（不是挤在一两个课时里）
- 起始状态：**CUSTOMER_REVIEW 43 题 + READY_TO_PAIR 7 题**
- 逐类均按课时轮转抽取（`spread()` 函数），避免"按 scope_id 排序取前 N"导致全挤在同一个课时

## 五、这 50 题怎么用

1. 全部走同一条流程：源库 → 运行包 prepare → 本地审校 → 导出 → 保存预演（不实际保存）
2. 逐题记 4 个量：起始状态、处理动作、结束状态、**耗时（秒）**、人工介入次数
3. 从实测数据算三档速率：顺利题均速 / 异常题均速 / 五类各自均速
4. 用这三档回推全书工期，并列出剩余异常类型清单交回 `fix/` 线继续批量处理

## 六、口径提醒

- 这 50 题**不代表**平台已完成 50 题。平台侧仍只有 42 题 / 143 框，且本轮零写入。
- 50 题闭环 = 本地候选完整 + 配对正确 + 导出成功 + 保存范围可核对。**不等于**平台已保存。
- 若某题在本地就无法消解（例如答案页真的没有该题答案），如实记为"需人工/需授权"，不要为了凑 50 而跳过。
