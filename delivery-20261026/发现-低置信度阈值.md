# 关键发现：91.9% 的"低置信度"是阈值造成的，不是识别质量问题

2026-10-26。B 侧 Lead 实测。脚本 `delivery/ocr_scores.py`，原始数据 `delivery/OCR置信度分布.json`。

## 一、现象

运行包把全书 **1,315 个候选里的 1,208 个（91.9%）** 标为 `LOW_OR_MISSING_OCR_CONFIDENCE`。
只有 9 个候选是 `READY_SOURCE_CHECKED`，其余 1,306 个全是 `NEEDS_REVIEW`。

客户拿到这样的包，观感就是"每一题都要我看"，等于没有自动化。

## 二、根因（代码级定位）

`bin/wholebook-single-entry/app/src/annotation/customer/quality.py:34`：

```python
if not refs or len(found)!=len(refs) or not scores or min(scores)<.97:
    issues.add('LOW_OR_MISSING_OCR_CONFIDENCE')
```

规则是：**取该题所有证据片段的 min(score)，只要最小值 < 0.97 就报警**。

## 三、实测分数分布（15,508 个片段）

| 统计 | 值 |
|---|---|
| 片段数 | 15,508 |
| 平均分 | 0.9489 |
| 中位数 (p50) | **0.9802** |
| p75 | 0.9951 |
| p90 | 0.9985 |
| p95 | 0.9992 |
| p25 | 0.9370 |
| p05 | 0.8084 |
| 最低 | 0.0344 |

**片段级看，识别质量是好的**：一半以上的片段在 0.98 以上，九成在 0.998 以上。

但换成"每题取最小片段"再看：

| 统计 | 值 |
|---|---|
| 每题最低分中位数 | **0.8736** |
| 每题最低分 p25 | 0.7646 |
| 每题最低分 p90 | 0.9647 |
| 每题最低分 p95 | 0.9787 |

## 四、这是统计陷阱

一道题平均引用 **11.8 个片段**（15,508 / 1,315）。
即使每个片段有 98% 概率 ≥0.97，一道题所有片段都 ≥0.97 的概率也只有 0.98^11.8 ≈ 79%——
而实际分布尾部更重，于是 **91.9% 的题至少有一个片段掉到阈值下**。

**"取最小值 + 高阈值"必然导致几乎全体报警**，这与识别质量无关。

## 五、按最低分分档看真实情况

| 每题最低分区间 | 题数 | 占比 | 怎么理解 |
|---|---|---|---|
| ≥0.97 | 103 | 7.8% | 完全干净 |
| 0.90–0.97 | 435 | 33.1% | 基本可信，个别片段偏低 |
| 0.80–0.90 | 372 | 28.3% | 需要看一眼 |
| 0.60–0.80 | 246 | 18.7% | 大概率有问题 |
| <0.60 | **159** | **12.1%** | 明显识别错误，必须修 |

- `min ≥ 0.90` 的题：**538 个（40.9%）**
- `min ≥ 0.80` 的题：**910 个（69.2%）**
- `min < 0.60` 的**坏题：159 个（12.1%）**

## 六、这意味着什么

1. **客户体验被一个阈值毁掉了**。真实需要人工修图/改字的题大约 159–400 道，
   不是 1,208 道。当前包把 3–7 倍的题量推给人，导致"自动化"名存实亡。
2. **不能简单调阈值**。0.97 是保守设计，直接降到 0.90 会把真错题也放过。
   正确的做法是**分层**：
   - `min ≥ 0.95` 且无其他 issue → 可自动通过
   - `0.90 ≤ min < 0.95` → 抽检
   - `min < 0.90` → 必审
   并保留 `FORMULA_LAYOUT_REVIEW`、`ANSWER_MISSING_OR_AMBIGUOUS` 等结构性 issue 作为独立门槛。
3. **需要用户决策**：这是质量门政策变更，不是纯工程改动。
   我可以实现分层，但"放宽到什么程度"必须由用户拍板。

## 八、区域齐备度（同一普查，这部分是好消息）

| 区域组合 | 题数 | 含义 |
|---|---|---|
| QCA（题干+选项+答案） | 364 | 选择题完整 |
| QA（题干+答案） | 391 | 填空/解答题完整 |
| QC（题干+选项） | 125 | 有选项缺答案 |
| Q（只有题干） | 435 | 缺答案或选项 |

**755 个题（57.4%）的题干+答案区域是齐的**（QCA 364 + QA 391）。
这是可直接交付审校的基数，比"0 题完整"的结论乐观得多。

## 九、结论

- 运行包"能跑"，但质量门的口径让 91.9% 的题看起来有问题。
- 真实可交付基数：**min≥0.90 的 538 题**，其中区域齐备的是一部分。
- 真实必须修的坏题：**159 题**。
- 这直接改变工期：不是 1,286 题全要人审，而是 159 必修 + 400 左右需抽检。
