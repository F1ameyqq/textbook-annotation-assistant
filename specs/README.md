## 0. 两套坐标系与换算

| | canvas（CSS） | SS = 图宽/canvas宽 | PADY |
|---|---|---|---|
| kind=q（p34.jpg 1219×1693） | 592×781 | 2.0591 | (781−1693/2.0591)/2 = **−20.60**（图比画布高，画布裁掉上下各 ~20.6 CSS） |
| kind=a（p174.jpg 1147×1620） | 462×781 | 2.4827 | (781−1620/2.4827)/2 = **+64.24**（图高只到 652.5 CSS，上下留白） |

```
源 → CSS：css_x = x / SS            css_y = y / SS + PADY
CSS → 源：x = css_x * SS            y = (css_y − PADY) * SS
```
这正是本侧 `bin/e2e_draw.py` / `bin/e2e_answer.py` 里已在用的换算
（`k = 源图宽/canvas 宽；pad = (canvas 高 − 源图高/k)/2`），所以 out.json 的源坐标可直接喂提交层。

### 2.1 为什么另做一份（以及上面那套的两处偏差）

1. **Q2 选项 C**：上面那套（min_ink=20）把 C 的框做成 `[103,781,224,791]` —— 只有 **10 源 px 高** 的细条，
   正好卡在分数 `√3/4` 的中间，把根号/分子切掉了。原因是「分数上横线」自成一薄带，
   每行墨点数 <20 被当噪声丢掉了。本适配版 `min_ink=5` 后 C 是 `[103,763,226,813]`，整条选项都在框里。
2. **Q7 选项 D**（`1/√5`）同理：`min_ink=5` 后行带 1023–1061 仍会切掉分子 `1`（每行只有 2–5 个墨点），
   所以适配版对 **选项框**加了一步「连续向上/向下扩到墨迹边界（最多 16 源 px，遇空白行即停）」，
   D 变成 `[1008,1013,1065,1064]`。
3. 另修了 A 侧一个过滤条件：原来「紧贴栏右边界 + 宽 <3 CSS」的块会被当扫描竖线丢掉，
   结果 Q7/Q8 题干末尾的 `）`（6–7 源 px 宽）也被丢了；阈值收到 2.0 CSS 后保住括号。
