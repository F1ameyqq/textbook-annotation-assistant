## 四、本轮踩到并已修掉的四个坑（都已写进代码）

1. **不选题型 → 提交被静默拦下**（不发请求、无报错）。`ensure_type()` 在提交前强制选题型，
   并按"是否识别到 ≥2 个选项"推断 选择/填空。
2. **reload 会清掉 XHR 钩子** → `window.__capR` undefined，识别/提交全抓不到。
   清场后必须重装 HOOK。
3. **框太小拖不出来**：题块只有一行时（Q5，31 源 px ≈ 15 CSS px），再内收 2px 就低于平台
   约 12 CSS px 的阈值，被当成单击。已加 `MIN_H=16 / MIN_W=24` 保护。
4. **提交后首次拖拽常失效**（画布重绘中）：`draw_box()` 最多重试 3 次，奇偶次换相反方向
   （避开已有框的 resize handle）。失败则**中止整轮**，绝不在同一题上继续堆框。

另有一次**序号错位事故**并已回滚：Q5 因上述原因未录上，导致 Q6 抢占 order 99，后续整体前移。
按 SOP 从大到小删除 99–103 后重录，现 96–104 与 Q2–Q10 一一对应。
